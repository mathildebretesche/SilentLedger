# Documentation: IERC5192

L'interface `IERC5192` définit le standard formel pour les **Tokens Non-Transférables à l'État Minimal** (couramment appelés `Soulbound Tokens` ou SBT).

## 📄 Standard EIP-5192
- **Lien EIP** : [https://eips.ethereum.org/EIPS/eip-5192](https://eips.ethereum.org/EIPS/eip-5192)
- Cette interface hérite de la normalisation `IERC165` pour autoriser la validation dynamique du support de cette fonctionnalité.
- Elle étend le comportement standard ERC-721 en rajoutant la gestion et l'exposition d'un état "verrouillé".

## ⚙️ Implémentation requise

### Événements

1. **`Locked(uint256 indexed tokenId)`**
   Doit être déclenché lorsqu'un token est figé. Pour les tokens liés à l'âme (comme dans `CertificationSBT`), cet événement est émis *dès l'émission* du token.

2. **`Unlocked(uint256 indexed tokenId)`**
   Déclenché lorsqu'un token redevient transférable. Dans une configuration purement Soulbound permanente, cet événement n'est pas utilisé mais défini pour la conformité de l'interface.

### Méthodes

**`locked`**
```solidity
function locked(uint256 tokenId) external view returns (bool);
```
Retourne obligatoirement `true` si le token désigné par l'id est figé (non libérable). Les appels sur un `tokenId` inexistant doivent provoquer une erreur (revert).
